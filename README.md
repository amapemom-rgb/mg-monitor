# MG-MONITOR

Система мониторинга розничных цен и скидок бренда на разных маркетплейсах и сайтах: сравнивает цену для покупателя между площадками, считает разбег и скидку, ведёт историю, строит дашборд с графиками по каждому товару и шлёт уведомления в Telegram при отклонениях.

Изначально сделана под конкретный бренд и конкретный набор площадок (Wildberries, Ozon, Yandex Маркет, Золотое Яблоко, Летуаль, сайт бренда на WooCommerce, плюс отключённые по умолчанию MegaMarket/Самокат/FlowWow), но архитектура рассчитана на то, чтобы под неё было легко добавить свои площадки — см. раздел «Как добавить новую площадку».

## Как это устроено

Система состоит из двух частей:

1. **Google Apps Script**, привязанный к Google-таблице (bound script), задеплоенный как веб-приложение. Хранит данные (лист «Товары», «История», «Настройки»), считает разбег цен и скидок, строит дашборд с графиками, шлёт алерты в Telegram по расписанию (триггеры Apps Script), и принимает данные от локального сборщика через HTTP POST.
2. **Локальный Python-скрипт на Mac** (`local-collector/`), который раз в день реальным браузером (Playwright поверх Chrome с постоянным профилем) заходит на страницы товаров и в личные кабинеты продавца/партнёра и собирает те цены, которые по разным причинам нельзя надёжно получить из облака: страницы защищены антиботом, официальный API не отдаёт нужное поле, либо отдаёт его с ошибками.

Оба компонента общаются через один и тот же веб-эндпоинт Apps Script (`doPost`), защищённый общим секретом.

### Почему не всё делает облако

Часть площадок (Ozon, Летуаль, Золотое Яблоко, сайт бренда, Yandex Маркет) отмечены в `Compare.js` как `LOCAL_ONLY_MPS_` — Apps Script вообще не пытается их собирать самостоятельно. Причины по каждой площадке разные и описаны в комментариях `fetchMp_()`/`fetchWb_()`/`fetchOzon_()` в `Compare.js`, коротко:

- **Ozon/Летуаль** — публичные страницы защищены антиботом, доступны только из настоящего браузера с живой сессией.
- **Ozon Кабинет через API** — `v5/product/info/prices` периодически путал цены между товарами.
- **Ozon Сайт (кабинет как источник)** — поле «Цена для покупателя» в кабинете продавца может отставать от реальной цены на публичной карточке (Ozon добавляет свои промо поверх цены продавца). Настоящая цена — только с публичной карточки.
- **Yandex Кабинет через API** (`offer-mappings`, `basicPrice.value`) — оказалось, что API отдаёт одно и то же число для разных товаров, то есть недостоверно. Реальная цена берётся со страницы `partner.market.yandex.ru` в браузере.
- **GoldApple** — старый серверный парсер иногда цеплял не ту цифру на странице и портил историю заниженными значениями.
- **WB Сайт** — публичный API `card.wb.ru` отдаёт цену без учёта скидки WB Кошелька (чёрную, а не красную цену), а покупателю по умолчанию показывается именно цена с Кошельком — её видит и сравнивает пользователь. Кабинет WB (обычная цена продавца, нужна только для расчёта скидки) по-прежнему собирается облаком через `discounts-prices-api.wildberries.ru`.

## Архитектура

```
┌─────────────────────────────┐        раз в сутки (launchd)       ┌──────────────────────────────┐
│   Mac: local-collector/      │ ───────────────────────────────►  │  Chrome + Playwright (CDP)    │
│   run_daily.py                │                                    │  постоянный профиль браузера  │
│                                │ ◄─────────────────────────────── │  (логины WB/Ozon/Yandex)      │
└───────────────┬───────────────┘        цены со страниц            └──────────────────────────────┘
                │
                │ HTTPS POST (OAuth Bearer + PW_SECRET)
                ▼
┌───────────────────────────────────────────────────────────────────────────┐
│  Google Apps Script — веб-приложение (PriceWriter.js: doPost)              │
│                                                                             │
│   • updates             → записывает цены в лист «Товары»                 │
│   • action=run_analysis → runSpreadSafe() (Compare.js): считает разбег,   │
│                             скидки, статус, шлёт Telegram-алерты,          │
│                             пишет строку в «Историю»                      │
│   • action=rebuild_dashboard → buildDashboard(): пересобирает графики     │
│   • action=export_products   → отдаёт список товаров/ссылок как CSV       │
└───────────────┬─────────────────────────────────────────────┬────────────┘
                │                                              │
                ▼                                              ▼
   Google Sheet: «Товары», «История»,              Триггеры Apps Script (по расписанию):
   «Настройки», «Дашборд», «Лог ошибок»             ежедневный сбор облачных площадок (WB
                                                     кабинет, Ozon кабинет), сторож повторов,
                                                     Telegram-уведомления
```

Ключевая идея: **Google-таблица — единственный источник правды** о списке товаров и ссылках (лист «Товары»). Локальный сборщик перед каждым запуском выгружает актуальный список товаров из таблицы в `tovary.csv` (`action=export_products`), поэтому добавление/переименование товара делается один раз — в самой таблице.

## Быстрый старт

### 1. Google-таблица и Apps Script

1. Создайте новую Google-таблицу.
2. Extensions → Apps Script, скопируйте туда все файлы из `apps-script/` (или используйте [`clasp`](https://github.com/google/clasp): `clasp clone <scriptId>` для существующего проекта, либо `clasp create` + `clasp push` для нового).
3. `appsscript.json` уже настроен на `"access": "ANYONE", "executeAs": "USER_DEPLOYING"` — это нужно, чтобы локальный скрипт с Мака мог писать в таблицу через веб-приложение.
4. Откройте таблицу — появится меню **MG-MONITOR**. Выполните по порядку:
   - «Шаг 1: Создать/Обновить структуру листов» (`setupSheets`) — создаёт листы «Товары», «Настройки» и т.д.
   - Меню **📊 Мониторинг цен → 1. Подготовить листы «Товары» и «Настройки»** (`setupSpread`) — добавляет колонки под площадки, разбег и статус.
5. Заполните лист «Товары»: название товара (это ключ, см. предостережение ниже), артикулы, ссылки на карточки товара по каждой площадке.
6. Задайте секреты в **Project Settings → Script properties** (не через ячейки таблицы!):
   `TELEGRAM_TOKEN`/`TG_BOT_TOKEN`, `TELEGRAM_CHAT_ID`/`TG_CHAT_ID`, `WB_API_KEY`, `OZON_CLIENT_ID`, `OZON_API_KEY`, `YANDEX_TOKEN`, `SCRAPINGBEE_API_KEY` (опционально: `ZENROWS_API_KEY`). Либо используйте меню «Шаг 2: Ввести API Ключи» (`setConfig`) для части ключей через диалоговое окно.
7. Deploy → New deployment → Web app, скопируйте URL вида `https://script.google.com/macros/s/XXXXX/exec`.
8. Задайте свой `PW_SECRET` — секрет, которым локальный сборщик подтверждает право писать в таблицу. Он **не хранится в коде**, только в Script Properties. Первый раз задать его можно одним HTTP-запросом (см. `PriceWriter.js`, действие `set_pw_secret` — при пустом Script Property запрос с любым текущим секретом примет новое значение один раз, дальше — только по старому секрету):
   ```bash
   curl -X POST 'https://script.google.com/macros/s/XXXXX/exec' \
     -H 'Content-Type: application/json' \
     -d '{"action":"set_pw_secret","secret":"","new_secret":"ваша-случайная-строка"}'
   ```
   (веб-приложение задеплоено с `executeAs: USER_DEPLOYING`, поэтому для вызова из локального скрипта также нужен OAuth-токен аккаунта, которым сделан деплой, см. `get_access_token()` в `run_daily.py`).
9. Меню **📊 Мониторинг цен → ⏱ Включить расписание** (`installSchedule`) — ставит триггеры ежедневного сбора и «сторожа» повторов.

### 2. Локальный сборщик на Mac

1. Установите зависимости:
   ```bash
   cd local-collector
   python3 -m venv venv && source venv/bin/activate
   pip install -r requirements.txt
   playwright install chromium
   ```
2. Скопируйте `config.example.py` → `config.py`, впишите `EXEC_URL` (адрес `/exec` из шага выше) и `SECRET` (тот же, что задали в `PW_SECRET`).
3. Для получения OAuth-токена скрипт переиспользует `~/.clasprc.json` (файл, который создаёт `clasp login`) — то есть на Маке должен быть установлен и авторизован [`clasp`](https://github.com/google/clasp) под тем же Google-аккаунтом, которым задеплоено веб-приложение:
   ```bash
   npm install -g @google/clasp
   clasp login
   ```
   (Если не хотите зависеть от clasp — замените `get_access_token()` в `run_daily.py` на свою реализацию OAuth, например сервис-аккаунт с доступом к таблице.)
4. Первый ручной запуск — авторизуйтесь во всех личных кабинетах руками: скрипт откроет Chrome с постоянным профилем (`/tmp/mg_chrome_profile` по умолчанию), войдите в WB, подтвердите 18+ на Yandex, войдите в Ozon Seller и Yandex Partner Market. Сессии сохранятся в профиле для последующих автоматических запусков — **пока профиль не будет очищен** (см. «Известные ошибки»).
5. Проверьте вручную:
   ```bash
   python3 run_daily.py
   ```
6. Настройте автозапуск через launchd: скопируйте `com.mgmonitor.dailycollect.plist` в `~/Library/LaunchAgents/`, поправьте пути под свои (`ProgramArguments`, `StandardOutPath`, `StandardErrorPath`), затем:
   ```bash
   launchctl load ~/Library/LaunchAgents/com.mgmonitor.dailycollect.plist
   ```
   `daily_wrapper.sh` реализует «догон»: если Мак был выключен в момент запланированного запуска, скрипт всё равно выполнится при следующем логине/пробуждении (проверяет `RunAtLoad` + файл-отметку `last_run.txt`).

## Как это работает день за днём

1. `daily_wrapper.sh` запускается по расписанию (или при логине, если пропущен) и вызывает `run_daily.py`, если сегодня ещё не было успешного запуска.
2. `run_daily.py`:
   - выгружает актуальный список товаров и ссылок из таблицы в `tovary.csv` (`action=export_products`);
   - запускает `collector.collect()` — открывает Chrome с сохранённым профилем, обходит карточки товаров по каждой площадке и кабинеты продавца/партнёра, парсит цены;
   - отправляет собранные значения в таблицу (`doPost` без `action`, просто `updates`);
   - вызывает `action=run_analysis` — облачная часть (`runSpreadSafe()` в `Compare.js`) досчитывает то, что ещё собирает сама (WB Кабинет, Ozon Кабинет), считает разбег и скидки по всем площадкам, пишет строку снимка в лист «История», при отклонениях шлёт Telegram-алерт;
   - вызывает `action=rebuild_dashboard` — пересобирает графики на листе «Дашборд».
3. Отдельно от локального сборщика Apps Script по своему расписанию (триггеры `dailyRun`/`dailyGuard`, меню «⏱ Включить расписание») тоже может пытаться запускать `runSpreadSafe()` — это резервный механизм на случай, если Мак не включён вовремя; облачные площадки (WB, при необходимости внешний парсинг через ScrapingBee) при этом всё равно обновятся, а `LOCAL_ONLY_MPS_`-площадки просто останутся с прошлым значением до следующего запуска локального сборщика.

## Известные ошибки и особенности площадок

Собрано по опыту эксплуатации — на будущее, чтобы не наступать на те же грабли повторно.

- **Разные юникодные «тонкие» пробелы как разделитель тысяч.** WB, Yandex и другие площадки используют разные пробельные символы (`\xa0` и т.д.) как разделитель разрядов в цене, и набор может отличаться от загрузки к загрузке (A/B-тесты на стороне площадки). Хардкодить конкретные символы в regex ненадёжно — уже дважды ловили баг, когда новый незнакомый пробел обрубал число. Решение — `_normalize_spaces()` в `collector.py`: заменяет ЛЮБОЙ юникодный пробел, кроме настоящего переноса строки, на обычный пробел перед разбором.
- **Кабинет продавца может отставать от реальной цены на публичной странице.** Обнаружено на Ozon: поле «Цена для покупателя» в личном кабинете показывало 1916 ₽, а на самой карточке товара реально было 2183 ₽ — Ozon накладывает свои платформенные промо поверх цены продавца, и кабинет не всегда отражает это в реальном времени. Правило: для цены, которую видит покупатель, всегда доверяйте публичной странице товара, а не личному кабинету.
- **Google Sheets embedded LineChart дропает полностью пустые серии** — если у товара нет ни одной точки данных по какой-то площадке за весь отображаемый диапазон (например, у одного товара просто нет карточки на Yandex), Google Sheets не рисует эту серию вообще, а массив `colors`, заданный по позиции, сдвигается для всех последующих серий — из-за этого разные товары получали разные (перепутанные) цвета площадок на графике. Решение: задавать цвета не через `setOption('colors', [...])`, а через `setOption('series', {индекс: {color: ...}})` — цвет привязывается к исходному индексу колонки и не сдвигается.
- **Профиль браузера и рабочие файлы в `/tmp` не переживают перезагрузку macOS.** `/tmp` может быть очищен между перезагрузками — если там же лежит сам код сборщика или список товаров, автоматика в какой-то момент молча перестаёт работать. В этом репозитории `collector.py`, `tovary.csv` и результаты вынесены в постоянную папку `local-collector/`, но профиль Chrome (`PROFILE_DIR` в `collector.py`) по историческим причинам всё ещё указывает на `/tmp/mg_chrome_profile` — если он будет очищен, нужно один раз заново войти во все личные кабинеты руками (см. «Быстрый старт», шаг 4). Рекомендуется перенести `PROFILE_DIR` в постоянную папку самостоятельно, если это станет проблемой.
- **«История» дедуплицируется по дню** (`appendHistory_()` в `Compare.js`): за один день по одной площадке хранится один снимок — при повторном запуске в тот же день старая запись за сегодня удаляется и пишется новая. Следствие: если вы правите значение в «Товары» вручную, это НЕ попадёт в «Историю» (и, соответственно, в графики дашборда и в расчёт скидки) само по себе — нужно после правки вызвать `action=run_analysis` (или меню «▶️ Собрать цены сейчас»), иначе следующий автоматический запуск может снова перезаписать сегодняшний снимок вашим старым/неправильным значением.
- **WB Сайт: чёрная цена vs красная (с Кошельком).** Публичный API `card.wb.ru` отдаёт цену без учёта скидки WB Кошелька — это не та цена, которую видит и платит обычный покупатель по умолчанию. Раньше облачная часть тихо перезаписывала верное значение с локального сборщика на эту неверную — сейчас облако вообще не пишет `WB Сайт`, только локальный сборщик (парсит реальную карточку).
- **Легаси-файлы, оставшиеся от более раннего прототипа** и не задействованные в текущей логике: `Main_Monitor.js` (`runMonitor`, `createDynamicTrigger` — недописанная функция мониторинга и отдельный часовой триггер, конфликтующий по смыслу с `installSchedule()` из `Compare.js`), `API_Marketplaces.js` (пустые функции-заглушки), `Dashboard.js` (старый дашборд, отключён), `test.js` (эксперимент с доступом к Летуаль через ZenRows, не был доведён до продакшена). Оставлены в репозитории для истории/референса — при желании можно удалить.
- **Колонка «Sportmaster»** создаётся `setupSheets()` в `Setup.js`, но нигде дальше не используется — по факту неиспользуемая легаси-площадка.

## Меры предосторожности (безопасность)

- **Все секреты — только в Script Properties (Apps Script) и `config.py` (Mac), не в коде.** `PW_SECRET` в `PriceWriter.js` намеренно читается из `PropertiesService.getScriptProperties()`, а не хардкодится — веб-приложение задеплоено с `"access": "ANYONE"` (см. `appsscript.json`), то есть URL `/exec` физически доступен кому угодно, кто его узнает; единственная защита — секрет в теле POST-запроса. Если вы форкаете этот репозиторий — **обязательно задайте свой `PW_SECRET`**, не оставляйте `CHANGE_ME`.
- `config.py` (реальные `EXEC_URL` и `SECRET` на Маке) добавлен в `.gitignore` — не коммитьте его. Используйте `config.example.py` как шаблон.
- Все остальные ключи API (WB, Ozon, Yandex, ScrapingBee, ZenRows, Telegram) должны храниться только в Script Properties Apps Script — никогда не вписывайте их прямо в ячейки таблицы или в код. В проекте есть функция-помощник `migrateSecretsFromSheet()` (`Compare.js`) — сканирует все листы таблицы на характерные паттерны токенов и переносит найденное в Script Properties, очищая ячейки.
- Если когда-либо секрет всё же «засветился» (закоммичен, отправлен в чат и т.п.) — смените его: новый `PW_SECRET` можно задать через `action=set_pw_secret` (см. «Быстрый старт», шаг 8 первого раздела), а остальные ключи — перевыпустить в личных кабинетах соответствующих площадок и обновить в Script Properties.
- Веб-приложение выполняется как `USER_DEPLOYING` — то есть от имени аккаунта, который сделал деплой, с его правами доступа к таблице. Не деплойте это на аккаунт с более широкими правами, чем нужно.
- Профиль браузера (`PROFILE_DIR` в `collector.py`) содержит живые сессии входа в личные кабинеты продавца/партнёра — храните Mac физически защищённым (пароль, диск с шифрованием), это фактически эквивалент сохранённого пароля.

## Как добавить новую площадку или сайт

Зависит от того, что у площадки доступно.

### Вариант A: у площадки есть открытый API с ценами (как WB/Ozon/Yandex)

1. Добавьте описание площадки в массив `MPS` в `Compare.js` (`code`, `title`, колонки `id`/`cab`/`site`/`disc`/`link`, `scrape: false`).
2. Напишите функцию `fetchНоваяПлощадка_(data, col)` по образцу `fetchWb_()`/`fetchOzon_()`/`fetchYandex_()`: получает данные из API, возвращает объект `{номер_строки: {site: цена_для_покупателя, cab: цена_в_кабинете}}`.
3. Подключите её в `fetchMp_()` (свитч по `code`).
4. Добавьте цвет площадки в `MP_COLORS_` (по фирменному цвету бренда площадки).
5. Ключ API — только в Script Properties, никогда в код.
6. Запустите `setupSpread()` (меню «📊 Мониторинг цен → 1. Подготовить листы...») — добавит нужные колонки в «Товары».
7. Включите площадку галочкой в «Настройки» (`Площадка: <название>`).

### Вариант B: у площадки нет API, но обычная страница товара парсится без браузера

1. Добавьте площадку в `MPS` с `scrape: true`.
2. Она автоматически пойдёт через `fetchExternalSite_()` → `extractSitePrice_()` → `parsePriceFromHtml_()` в `Compare.js` — универсальный парсер, который по очереди пробует: микроразметку Schema.org (`itemprop="price"`), Open Graph, характерные JSON-поля (`price`/`salePrice`/...), разметку WooCommerce, и в последнюю очередь — любое число рядом с «₽»/«руб» в тексте страницы.
3. Если бесплатный прямой запрос не проходит (антибот) — подключится ScrapingBee (`SCRAPINGBEE_API_KEY` в Script Properties), с эскалацией по стоимости (см. `SB_MODES`/`ZR_MODES`).
4. Если и это не помогает (площадка требует полноценный браузер с сессией) — см. вариант C.

### Вариант C: площадка требует настоящий браузер (антибот, авторизация)

Это путь, которым сейчас собираются Ozon, Летуаль, GoldApple, Yandex и сайт бренда.

1. В `collector.py` добавьте функцию по образцу `ozon_site_price_from_text()`/`ym_price_from_text()`/`price_from_title()` — она получает текст страницы (`page.inner_text("body")`) или заголовок (`page.title()`) и регулярным выражением достаёт цену. Не забудьте `_normalize_spaces()` перед разбором (см. «Известные ошибки»).
2. В `load_products()`/`collect()` добавьте загрузку нужной ссылки из CSV и вызов новой функции внутри цикла по товарам, запись результата в `results[p['name']]['новое_поле']`.
3. Если площадке нужна авторизация — она пройдёт через тот же постоянный профиль Chrome (`PROFILE_DIR`), достаточно один раз войти руками.
4. В `PriceWriter.js` → `writeSitePrices_()` добавьте новое поле в `fieldMap` (сопоставление ключа из Python с названием колонки в «Товары»).
5. В `Compare.js` добавьте код площадки в `LOCAL_ONLY_MPS_`, опишите в `MPS` (как в варианте A, но без функции `fetchНоваяПлощадка_` — она не нужна, раз облако эту площадку не собирает).
6. Добавьте колонку-ссылку в `export_products_csv()`/`writeSitePrices_()` при необходимости и в лист «Товары» вручную (или через `setupSpread()`).
7. Добавьте цвет площадки в `MP_COLORS_`.

## Диагностика и частые проблемы

Встроенные диагностические функции (запускаются из редактора Apps Script или через меню):

- **«📊 Мониторинг цен → 🧪 Проверить источники цен»** (`testSources`) — по каждой включённой площадке показывает, сколько строк получили данные, и пример ответа.
- **«🧪 Проверить скрейперы и кредиты»** (`checkScrapers`) — проверяет, заданы ли ключи ScrapingBee/ZenRows, делает тестовый запрос, показывает остаток кредитов.
- **«🧪 Тест Telegram»** (`testTelegram`) — отправляет тестовое сообщение в чат.
- `listPropertyKeys()` — какие ключи заданы в Script Properties (без значений).
- Лист «Лог ошибок» — сюда пишутся все сбои источников с указанием причины.
- Лист «Инструкция» (генерируется `buildInstructionSheet()`) — подробная инструкция на русском прямо в самой таблице, для человека, который будет с ней работать день за днём (не разработчика).
- На Маке: `local-collector/run.log`, `wrapper.log`, `launchd.out.log`, `launchd.err.log` — логи каждого запуска. `last_run.txt` — отметка последнего успешного дня (используется для «догона» пропущенных запусков).

Если сбор не удаётся много дней подряд — бот пришлёт уведомление в Telegram с перечнем площадок, которые молчат. Дальше три способа перезапустить сбор немедленно, не дожидаясь следующего дня: написать боту «Попробуй снова», поставить галочку «Повторить сбор сейчас» в «Настройках», либо выполнить меню «🔁 Повторить сбор».
